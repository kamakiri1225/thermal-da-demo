# OpenFOAMの温度計算にセンサ情報を混ぜる: laplacianFoamとOptimal Interpolationによるデータ同化

## この記事で扱うこと

この記事では、OpenFOAM の `laplacianFoam` で計算した1次元熱伝導の温度場に、センサ観測を使ってデータ同化を行った例を整理します。

今回使った手法は **Optimal Interpolation (OI)** です。

ポイントは、OpenFOAMのソルバを改造せず、さらにOpenFOAM内部の離散化行列をPython側で再現しないことです。OpenFOAMは温度場を予測する計算エンジンとして使い、Python側で観測値を使って温度場を補正します。

## 読んでほしい人

このメモは、次のような人を想定しています。

- OpenFOAMの計算結果に実験センサ値を反映したい人
- データ同化をCFDや熱解析に使ってみたい人
- カルマンフィルタの状態遷移行列を作るのが難しいと感じている人
- ソルバ改造なしで、まず外部Pythonからデータ同化を試したい人

## 対象とした課題

対象は1次元の熱伝導棒です。

OpenFOAM側では `laplacianFoam` を使い、左端に温度勾配、右端に固定温度を与えます。

```text
左端: fixedGradient
右端: fixedValue 20 degC
```

今回はツイン実験として、まずOpenFOAMで「真値」を作りました。

```text
真値   : G_TRUE  = 100 degC/m
モデル : G_MODEL =  50 degC/m
```

`G_MODEL` を真値の50%にしているのは、データ同化を使わない場合と使った場合の差を見やすくするためです。つまり、わざと境界条件を大きく間違えたモデルを作り、センサ観測でどこまで引き戻せるかを見ています。

言い換えると、今回の実験では、かなり外れた条件から計算を始めています。

```text
本当の熱入力 : G_TRUE  = 100 degC/m
間違った熱入力: G_MODEL =  50 degC/m
```

`G_MODEL = 50 degC/m` は、真値の半分しか熱を入れていない設定です。そのため、データ同化を使わずにOpenFOAMを走らせると、温度場は真値から大きく外れます。

ここに、Node 0 と Node 4 の温度だけを「観測値」として与えます。するとOIは、その観測点で分かったズレを使って、OpenFOAMの温度場を補正します。

重要なのは、観測しているのは一部の点だけだということです。それでも、背景誤差共分散 `B` によって補正が周囲の節点にも広がるため、観測していない点も真値に近づく傾向が出ます。

つまり今回示したいことは、次です。

```text
間違った条件で計算すると全体の温度場は大きく外れる。
しかし、一部の点で実測値を与えると、
データ同化によって未観測点も含めて真値に近づく傾向がある。
```

ただし、これは「すべての点が必ず正解になる」という意味ではありません。センサ位置、背景誤差共分散 `B`、観測ノイズ、境界条件の間違い方によって、補正の効き方は変わります。

## なぜOIを使ったのか

最初に考えたのは、カルマンフィルタ型のデータ同化でした。

ただしカルマンフィルタでは、予測誤差共分散を時間発展させるために、状態遷移行列のようなものが必要になります。

$$
\mathbf{P}_k^-
=
\mathbf{F}_k
\mathbf{P}_{k-1}^+
\mathbf{F}_k^T
+
\mathbf{Q}
$$

自作の1次元熱伝導差分モデルなら、`F` や `A_d` は作りやすいです。支配方程式も離散化も自分で分かっているからです。

しかしOpenFOAMでは事情が違います。OpenFOAM内部では、メッシュ、境界条件、離散化スキーム、線形ソルバなどが絡みます。Python側で「OpenFOAMと同じ時間発展行列」を作ったつもりでも、本当に一致しているとは限りません。

そこで今回は、`A_d` を使わない方法として OI を採用しました。

OIでは、OpenFOAMの内部方程式をPython側で再現しません。OpenFOAMの予測値をそのまま受け取り、固定した背景誤差共分散 `B` と観測誤差共分散 `R` を使って補正します。

## OIの簡単な理論

OIの更新式は次です。

$$
\mathbf{x}^a
=
\mathbf{x}^f
+
\mathbf{K}
\left(
\mathbf{y}
-
\mathbf{H}\mathbf{x}^f
\right)
$$

ここで、

| 記号 | 意味 |
|---|---|
| `x_f` | OpenFOAMによる予測値 |
| `x_a` | データ同化後の解析値 |
| `y` | センサ観測値 |
| `H` | 状態ベクトルからセンサ位置だけを取り出す行列 |
| `K` | OIゲイン |

括弧の中はイノベーションです。

$$
\mathbf{d}
=
\mathbf{y}
-
\mathbf{H}\mathbf{x}^f
$$

これは「観測値と予測値の差」です。

OIゲインは次で計算します。

$$
\mathbf{K}
=
\mathbf{B}\mathbf{H}^T
\left(
\mathbf{H}\mathbf{B}\mathbf{H}^T
+
\mathbf{R}
\right)^{-1}
$$

この式はカルマンゲインとよく似ています。ただし、カルマンフィルタでは時間発展させた予測誤差共分散 `P^-` を使うのに対し、OIでは固定した背景誤差共分散 `B` を使います。

```text
Kalman Filter:
K = P^- H^T (H P^- H^T + R)^-1

Optimal Interpolation:
K = B H^T (H B H^T + R)^-1
```

そのため、今回の `K` は「カルマンゲイン型の重み」ですが、正確には **OIゲイン** と呼ぶのが分かりやすいです。

## Bは何を表しているのか

`B` は、OpenFOAM予測の誤差が空間的にどのように広がるかを表す行列です。

今回の実装では、支配方程式から `B` を作らず、セル間距離から作りました。

$$
B_{ij}
=
\sigma_b^2
\exp
\left(
-
\frac{d_{ij}^2}{2L_c^2}
\right)
$$

意味は単純です。

```text
近いセル同士  : 似た誤差を持ちやすい
遠いセル同士  : 誤差の関係は弱い
```

もう少し具体的に言うと、`B` は「観測点で分かったズレを、他の点へどれくらい伝えてよいか」を決めるための地図です。

たとえば Node 4 にセンサがあるとします。Node 4 の予測温度が実測より低ければ、Node 4 の近くの節点も同じように低く予測されている可能性があります。この「一緒に間違っていそう」という関係を `B` が表します。

ただし、`B` だけではまだ補正量は決まりません。センサ自体にもノイズがあるからです。

そこで、OIでは `B` と観測誤差 `R` からゲイン `K` を作ります。

$$
\mathbf{K}
=
\mathbf{B}\mathbf{H}^T
\left(
\mathbf{H}\mathbf{B}\mathbf{H}^T
+
\mathbf{R}
\right)^{-1}
$$

この式の意味は次です。

| 部分 | 意味 |
|---|---|
| `B H^T` | 各節点とセンサ位置の誤差のつながり |
| `H B H^T` | センサ位置で予測される誤差の大きさ |
| `R` | センサ観測のノイズ |
| `(H B H^T + R)^-1` | モデル誤差と観測誤差のバランスを取る重み |

1つのセンサだけなら、補正は次のように見られます。

$$
x_i^a
=
x_i^f
+
\frac{B_{i,s}}{B_{s,s} + R}
\left(
y_s - x_s^f
\right)
$$

つまり、

```text
センサで分かった差
×
その差を節点 i に伝える割合
```

で補正しています。

この割合を全節点・全センサについてまとめたものが `K` です。

この式をもう少し分解します。

| 部分 | 意味 |
|---|---|
| `x_i^f` | 補正前の節点 i の温度 |
| `x_i^a` | 補正後の節点 i の温度 |
| `y_s` | センサ s で測った温度 |
| `x_s^f` | センサ位置 s におけるOpenFOAM予測温度 |
| `y_s - x_s^f` | センサ位置で分かった予測のズレ |
| `B_{i,s}` | センサ s のズレを節点 i に伝えてよい強さ |
| `B_{s,s}` | センサ位置 s の予測誤差の大きさ |
| `R` | センサ観測の誤差の大きさ |

たとえば、センサ位置で次のような差があったとします。

```text
実測温度 y_s       = 30 degC
OpenFOAM予測 x_s^f = 26 degC
```

このとき、センサ位置で分かったズレは、

```text
y_s - x_s^f = 30 - 26 = 4 degC
```

です。

次に、補正したい節点 `i` がこのセンサと強く関係しているなら、たとえば重みが `0.8` になります。

```text
B_{i,s} / (B_{s,s} + R) = 0.8
```

この場合、節点 `i` にはセンサで分かった4 degCのズレのうち、80%を反映します。

```text
補正量 = 0.8 * 4 = 3.2 degC
```

もし補正前の節点 `i` の温度が、

```text
x_i^f = 24 degC
```

なら、補正後は、

```text
x_i^a = 24 + 3.2 = 27.2 degC
```

になります。

センサから遠い節点では重みが小さくなります。たとえば重みが `0.1` なら、

```text
補正量 = 0.1 * 4 = 0.4 degC
```

だけ補正されます。

つまりOIは、センサ位置のズレを全節点に同じ量だけ足す方法ではありません。`B` と `R` から決まる重みによって、場所ごとに補正量を変える方法です。

では、その重みはどう求めたのでしょうか。

今回のプログラムでは、まず節点間の距離から `B` を作っています。

```python
x = np.arange(N_NODES) * DX
distance = np.abs(x[:, None] - x[None, :])
B = BACKGROUND_ERROR_STD**2 * np.exp(
    -(distance**2) / (2.0 * CORRELATION_LENGTH_M**2)
)
```

これは、

```text
近い節点ほど同じように間違っている可能性が高い
遠い節点ほど同じ誤差を持つ可能性が低い
```

という仮定です。

次に、観測ノイズから `R` を作ります。

```python
R = np.eye(n_obs) * OBS_NOISE_STD**2
```

最後に、`B` と `R` からOIゲインを作ります。

```python
gain = B @ H.T @ np.linalg.inv(H @ B @ H.T + R)
```

この `gain` が、センサで分かったズレを各節点に配る重み表です。

現在の設定では、

```text
BACKGROUND_ERROR_STD = 3.0 degC
CORRELATION_LENGTH_M = 0.06 m
OBS_NOISE_STD = 0.05 degC
DX = 0.03 m
```

です。

1つのセンサだけで見れば、重みの目安は次のようになります。

| センサからの距離 | 重みの目安 |
|---:|---:|
| 0.00 m | 約 1.00 |
| 0.03 m | 約 0.88 |
| 0.06 m | 約 0.61 |
| 0.09 m | 約 0.32 |
| 0.12 m | 約 0.14 |

つまり、センサ近くは強く補正し、遠くは弱く補正するように重みを作っています。

今回の設定は次です。

```text
BACKGROUND_ERROR_STD = 3.0 degC
CORRELATION_LENGTH_M = 0.09 m
OBS_NOISE_STD = 0.05 degC
```

`B` を固定しているため、OpenFOAMの離散化行列を知る必要はありません。一方で、`B` の作り方が補正結果に強く効くため、相関長の決め方は重要です。

## 解析設定の手順

今回の解析は次の流れで行いました。

1. OpenFOAMケース `case_da` を用意する
2. 10セルの1次元熱伝導メッシュを作る
3. `G_TRUE = 100 degC/m` でOpenFOAMを走らせ、真値を作る
4. `G_MODEL = 50 degC/m` でOpenFOAMを独立に走らせ、DAなし結果を作る
5. Node 0 と Node 4 にセンサがあると仮定する
6. 真値からセンサ観測値を作る
7. `G_MODEL` のOpenFOAM予測を、OIで逐次補正する
8. 補正後の温度場を次ステップのOpenFOAM初期場として書き戻す
9. DAなしとDAありのRMSEを比較する

プログラム上は、OpenFOAM予測を次のように1ステップずつ実行しています。

```python
ofi.write_field(k * DT, x_current, gradient=g_model_series[k])
ofi.run_step(k * DT, (k + 1) * DT)
x_pred = ofi.read_field((k + 1) * DT)
```

OI更新は次です。

```python
innovation = y - H @ x_pred
x_da = x_pred + gain @ innovation
```

そして次ステップへ渡します。

```python
x_current = x_da
```

## 計算はどのように回しているのか

今回の `with_da` では、OpenFOAMを最初から最後まで一気に走らせてから後処理しているわけではありません。

次のように、同化時刻ごとにOpenFOAMを止めて、Pythonで補正し、補正後の温度場を次の初期条件として書き戻しています。

```text
OpenFOAMを10秒進める
  ↓
温度場 T をPythonで読む
  ↓
センサ観測との差から OI 補正を行う
  ↓
補正後の温度場をOpenFOAMの次の初期場として書く
  ↓
OpenFOAMを次の10秒へ進める
```

このため、データ同化ありケースでは、OpenFOAMを時間ステップごとに起動しています。

今回の設定では `N_STEPS = 90` なので、`with_da` だけで `laplacianFoam` を90回実行しています。

また、今回は比較用に次の3つを計算しています。

```text
truth      : 真値を作るための計算
model_only : データ同化なしの比較用計算
with_da    : データ同化ありの計算
```

したがって、ツイン実験全体では概念的に、

```text
90回 + 90回 + 90回 = 270回
```

`laplacianFoam` を実行しています。

ただし、実測データを使う本番では `truth` は不要です。最低限は `with_da` だけでよく、DAなし比較も見るなら `model_only` と `with_da` の2本になります。

計算時間が問題になる場合は、同化間隔を毎ステップではなく、30秒ごと、60秒ごとにするのが現実的です。

```text
毎10秒同化  : 細かく補正できるが計算回数が多い
毎30秒同化  : 計算回数を約1/3にできる
毎60秒同化  : 計算回数を約1/6にできる
```

この同化間隔は、今後の実験データ版で重要な検討項目です。

## 結果から言えること

今回の結果から言えることは、次の通りです。

1. 熱入力を大きく間違えたOpenFOAM予測は、DAなしでは真値から外れる
2. OIを使うと、センサ位置の温度は真値にかなり近づく
3. センサがない節点にも、背景誤差共分散 `B` を通じて補正が広がる
4. 結果として、全節点平均RMSEが大きく下がった
5. ただし、補正の広がり方は `B` の作り方に依存する

今回の例では、熱入力を `100 degC/m` ではなく `50 degC/m` として計算したため、DAなしの温度場は大きく外れました。そこへ Node 0 と Node 4 の温度情報を与えることで、OIが温度場全体を観測側へ引き戻しました。

この意味で、今回の結果は、

```text
部分的な温度観測を使うことで、
間違ったOpenFOAM計算を全体として正しい方向へ修正できる
```

ことを示しています。

ここで大事なのは、OIが「正解を知っているから近づいた」のではないという点です。

OIに入れているのは、Node 0 と Node 4 の観測値だけです。それ以外の節点は、`B` による空間相関を使って推定しています。

そのため、この数値実験は、

```text
少数センサから未観測点の温度を推定する
```

という実験計画につながります。

この結果から、少なくとも今回の1次元熱伝導のツイン実験では、

```text
OpenFOAM予測 + 少数センサ + OI
```

によって、間違った境界条件で走らせたOpenFOAM予測を観測側へ近づけられることが確認できました。

## この手法の利点

今回のOI連成には、次の利点があります。

- OpenFOAMソルバを改造しなくてよい
- OpenFOAMの時間発展行列 `A_d` を作らなくてよい
- `laplacianFoam` 以外のソルバにも考え方を広げやすい
- Python側の実装が比較的軽い
- DAなしとDAありを比較しやすい
- センサ観測をシミュレーション場全体へ広げる考え方を試せる

特に大きいのは、OpenFOAMをブラックボックスの予測器として扱えることです。ソルバ内部に手を入れる前の第一段階として使いやすい方法です。

## デメリットと注意点

一方で、OIには明確な限界もあります。

- `B` を固定で与えるため、補正の広がり方が `B` の設計に依存する
- `CORRELATION_LENGTH_M` の選び方で結果が変わる
- 境界勾配 `G` 自体を推定しているわけではない
- 観測点が少ない場所では補正が弱くなる
- 強い非線形現象や複雑な3次元流れでは、固定した `B` だけでは不十分になりやすい

今回の結果でも、センサから遠い節点では補正の効き方に差があります。これは、OIがセンサ情報を `B` に従って空間的に広げる方法だからです。

## これは何に活かせるのか

この手法は、シミュレーションと実測値をつなぐための入口になります。

たとえば、次のような用途に発展できます。

- 熱伝導解析で、少数の温度センサから全体温度場を推定する
- OpenFOAMの計算結果を実験値に逐次的に近づける
- 実験中の温度場をリアルタイムに推定する
- 境界条件や熱入力が不確かな解析で、観測を使って計算のズレを抑える
- より高度なEnKFやパラメータ同化に進む前の検証モデルにする

今回の例では温度場を直接補正していますが、次の段階では熱入力倍率や境界条件そのものを推定する方向も考えられます。

## 研究の問い

今回の実験から、次の研究の問いが見えてきます。

1. 少数の温度センサから、どこまで未観測領域の温度場を復元できるか
2. OIの背景誤差共分散 `B` は、どのように設計すれば物理的に自然な補正になるか
3. センサ位置をどこに置けば、同化効果が最大になるか
4. 温度場を直接補正する方法と、熱入力や境界条件を推定する方法では、どちらが実験系に適しているか
5. OIで十分な範囲と、EnKFやパラメータ同化へ進むべき範囲はどこで分かれるか
6. OpenFOAMソルバを改造せずに、どこまで実験データを反映した解析ができるか

このサンプルの意義は、OpenFOAMとデータ同化をつなぐ最初の足場を作ったことです。

最終的な目的は、単に計算結果をきれいにすることではありません。実験で限られた点しか測れない状況でも、物理モデルと観測データを組み合わせて、見えない温度場や不確かな境界条件を推定することです。

その意味で、今回のOIはゴールではなく、OpenFOAMを使った実験融合型シミュレーションへ進むための第一歩です。
