# はじめてのデータ同化 ― 大学初学者のための超ていねい解説

この文書は「データ同化って結局なにをしているの？」を、予備知識ゼロから
順番に理解するためのものです。数式は最後にだけ出てきます。まずは絵と言葉で。

---

## 0. ひとことで言うと

> **たった数個の測定値を使って、間違った予測を正しい状態へ「引き戻す」技術**

このフォルダ(104)がやっているのは、次の実験のシミュレーション版です。

- 金属の円筒を、横からヒーターで温める(102_0 の設定)
- 温度計を数個、変位センサを数個だけ貼る
- **中身の温度分布は直接は測れない**(センサは表面の数点だけ)
- それでも「数点の測定」から**全体の温度分布**を推定したい

これを可能にするのがデータ同化です。

---

## 1. なぜ難しいのか(問題の設定)

シミュレーション(OpenFOAM)は、初期状態を与えれば温度がどう変化するか計算できます。
でも現実には:

- **初期状態が正確にわからない**(部屋の温度ムラ、材料のばらつき…)
- **ヒーターの発熱量が正確にわからない**(安物ヒーターは表示どおり出ない)

初期状態や発熱量が少しでも違うと、計算した温度は本物とズレていきます。
下の灰色の線(同化なし)がそれです ― **でたらめな初期値から出発すると、
ずっと間違ったまま**。

![温度時刻歴](img/rom_fem_temperature.png)

黒い破線が「本物(真値)」、灰色が「間違った初期値のまま計算した結果」。
600秒たっても真値に戻りません。これをどうにかしたい、というのが出発点です。

## 2. データ同化のアイデア(気持ち)

料理でたとえます。

- レシピ(モデル)どおり作っても、オーブンの癖で焼き上がりがズレる
- だから**途中で味見(観測)**して、火加減(状態)を直す
- 味見は数回だけ。でも、その情報で全体を調整できる

データ同化はこれを数学的にやります:

```
   予測する  →  数点だけ測る  →  測定と予測のズレから全体を直す  →  また予測する …
  (シミュレーション)  (観測)          (これがキモ)
```

ポイントは「**数点しか測っていないのに、測っていない場所まで直せる**」こと。
なぜそんなことができるのか? ― それは「温度分布には物理的なつながりがあって、
ヒーター側が熱ければ隣も熱い、という**相関**を使うから」です(§6で数式に)。

上の図の青い線(データ同化あり)を見てください。**でたらめな初期値から出発しても、
数点の観測(赤い点)を使うと、数十秒で真値(黒破線)にピタッと張り付きます**。
しかも hot/cold(観測点)だけでなく、**測っていない mid/top/core まで直っています**。

これを**3次元の温度分布**で見ると、もっと直感的です(OpenFOAM 版、円筒を半分に切って
内部を表示。`run/plot_da_temperature_field3d.py`):

![データ同化後の3D温度分布](img/da_temperature_field3d.png)

- **でたらめ(左)**: 全体が一様に高温(27.6℃)で、分布がのっぺり間違っている
- **データ同化後(中)**: ヒータ側(+X)が熱く反対側が冷たい**正しい空間分布**に補正
- **真値(右)**: 中央とそっくり

温度2点(hot/cold)しか測っていないのに、**円筒全体の3次元温度分布が真値に一致**しました。

**時刻歴アニメーション**(左=データ同化後 / 右=真値、`run/make_da_gifs.py`):

![温度分布 DA vs 真値](img/da_vs_truth_temperature.gif)

t=0 では左(データ同化後)がでたらめに高温、右(真値)は 20℃ で**食い違って**いる。
しかし最初の観測が入ると左が右に**吸い付き**、以降ヒータ ON(0-300s)で温まり
OFF(300-600s)で冷める全過程を通じて、左右がぴったり一致し続ける。

## 3. 「ROM」とは何か、なぜ使うのか

ROM = Reduced Order Model = **縮約モデル**(軽い代用モデル)。

本物の OpenFOAM は、円筒を約2万個の小さなマス(セル)に分けて計算します。
とても正確ですが、**1回の計算に数分〜1時間**かかります。データ同化では
同じ計算を何十回も繰り返すので、これでは重すぎます。

そこで、円筒の温度を**5点の代表温度**(hot/mid/cold/top/core)だけで表す
超シンプルな模型を作ります。これが ROM です。中身は「熱の伝わりやすさ」で
つないだ5個の点の温度方程式(§8)。**計算は一瞬**(0→600秒が数秒)。

各ノードは次のエネルギー保存則(集中定数)に従います:

$$C_i \frac{dT_i}{dt} = \sum_j K_{ij}(T_j - T_i) - h(T_i - T_\mathrm{air}) + \dot Q_i(t)$$

これは本物が解く熱伝導**偏微分方程式**を有限体積法で離散化し、
セルを2万個から5個へ極端に粗くしたものです(別物の近似ではなく同じ物理式)。
未知の係数 $\{C_i, K_{ij}, h\}$ は、本物のOpenFOAM(102_0)の温度履歴に
一致するよう**最小二乗で校正**します:

$$\hat{\boldsymbol\theta} = \arg\min_{\boldsymbol\theta} \sum_{n,p}\big(T_p^\mathrm{ROM}(t_n;\boldsymbol\theta) - T_p^\mathrm{OF}(t_n)\big)^2$$

その結果、当てはめ誤差は **RMSE 0.012℃** まで下がり、しかも校正で得た全熱容量
$\sum C_i \approx 1191\,\mathrm{J/K}$ は鋼2.49kgの $\rho c_p V \approx 1195\,\mathrm{J/K}$ と
一致します(数字合わせでなく物理的に正しい)。

> **なぜ5点で本物に一致するのか、PDE→ODEの導出、校正の逆問題、校正値の妥当性**は
> 別紙 [`03_rom_derivation.md`](03_rom_derivation.md) で数式を尽くして解説しています。
> 「お気持ち」ではなく導出で納得したい方はそちらへ。

こうして ROM は「前進が速い」「挙動が本物と一致」の2条件を満たすので、
データ同化の考え方を**待たずに何度でも試せる**教材になります。

> 本物どおりの精度が要るときは OpenFOAM 版(`run/run_openfoam_fem_enkf.py`)、
> 仕組みを理解したいときは ROM 版(`run/run_rom_fem.py`)、と使い分けます。

## 4. 「双子実験(そうじじっけん)」とは ― 何に合わせ、何が成果か

手法が本当に効くか確かめるには「正解」を知っている必要があります。
そこで**わざと自分で正解を作り**、それを隠して数点だけ測り、当てられるか試します。
これを双子実験(OSSE: Observing System Simulation Experiment)と呼びます。
以下、このROMで実際に使っている**具体的な数値**で示します。

### ステップ1: 正解(真値)を作る ― 「合わせに行く相手」

正しいパラメータで ROM を1回だけ動かします:

- 発熱量 $Q_\mathrm{true} = 15\,\mathrm{W}$(倍率 $q=1.0$)、放熱 $h_\mathrm{true}=0.0236\,\mathrm{W/K}$
- 初期温度 = 全ノード 20.0℃(部屋温度で一様)

得られる真の温度(これが**推定で合わせに行く相手**):

| 時刻 | hot | mid | cold | top | core |
|------|-----|-----|------|-----|------|
| 0 s | 20.0 | 20.0 | 20.0 | 20.0 | 20.0 |
| 300 s(加熱終) | 25.57 | 23.94 | 22.72 | 24.21 | **23.76** |
| 600 s(冷却後) | 23.60 | 23.59 | 23.60 | 23.60 | **23.61** |

太字の core は**測っていない潜在ノード**。ここまで当てられるかが見どころ。

### ステップ2: 観測を作る ― 「手元にある少ない手がかり」

真値のうち **hot と cold の2点だけ**を取り出し、実際の温度計を模して
**測定ノイズ**(標準偏差 0.30℃ の正規乱数)を足します。これを **20秒ごとに30回**。

$$y_n = \big[\,T_\mathrm{hot}(t_n),\ T_\mathrm{cold}(t_n)\,\big] + \varepsilon_n,\quad \varepsilon_n\sim N(0,\,0.30^2)$$

**mid / top / core は一切測りません**。手がかりは温度2点×30時刻だけ。

### ステップ3: わざと間違える ― 「でたらめ」の中身

真値を忘れて、**60個の分身(アンサンブル)**をでたらめな初期状態から出発させます。
「でたらめ」の具体的な中身は:

- **初期温度**: 各ノード・各分身を **10〜50℃の一様乱数**でバラバラに(真の20℃を知らない)。
  分身平均の初期温度は真値から **RMSE 9.74 K** も外れている
- **発熱量の倍率** $q$: 平均 1.83・ばらつき 0.79(真値 1.0 に対し過大)
- **放熱係数** $h$: 平均 0.52・ばらつき 0.29(真値 0.0236 の**20倍以上**過大)

つまり「初期温度も、ヒータの強さも、放熱の速さも全部間違っている」状態から出発します。

### ステップ4: 成果は何か ― 採点(RMSE)

正解を握っているので、推定(分身の平均)と真値のズレを

$$\mathrm{RMSE}(t) = \sqrt{\frac{1}{5}\sum_{i=1}^{5}\big(\bar T_i(t) - T_i^\mathrm{true}(t)\big)^2}$$

で採点できます。**成果**は次の3点(§2 の温度図と §7 の RMSE 図で確認):

1. **温度RMSE 9.74 K → 0.039 K**(観測ノイズ0.30Kより小さい水準まで収束)
2. **測っていない mid/top/core まで真値に一致**(core も 0.04K 精度)
3. **未知パラメータ**も回復($q:1.83\to\approx1.0$、$h$ も真値方向へ)

「でたらめから出発しても、温度2点の観測だけで、隠した全体像とパラメータまで
言い当てられた」― これが双子実験で示したい成果です。

## 5. 「アンサンブル」とは ― たくさんの分身で不確かさを表す

初期状態がわからない、を**1つの値**で表すのは無理です。そこで
「ありえそうな初期状態」を**たくさん(例: 60個)ばらまきます**。この分身の集団を
アンサンブルと呼びます。

- 分身がバラバラ = 不確かさが大きい
- 分身がまとまっている = 自信がある

観測が来るたびに、**各分身を観測に近づけ、集団をキュッと真値に寄せます**。
これがアンサンブルカルマンフィルタ(EnKF)。分身の**ばらつき**から
「どの向きに直すべきか(相関)」を自動で学ぶのがミソです。

## 6. 変位も使う(104 の新しいところ)

温度計だけでなく、**熱で伸びた変位**も観測に使えます(実験の変位センサ)。
金属は温まると伸びるので、上面の持ち上がり(変位)は温度の情報を持っています。

![変位時刻歴](img/rom_fem_displacement.png)

この図は「温度を直したら、そこから予測される変位も自動的に真値に一致した」
ことを示しています(灰=でたらめ、青=同化後、黒破線=真値)。

### データ同化された変位の「分布」(変形形状)

上は2点の時刻歴。では**変位の空間分布(変形した形)**はどうなったか?
OpenFOAM 版のデータ同化後の温度場を FrontISTR に通し、変形形状を描いたのが下図
(`run/plot_da_displacement_field.py`、変形は約2000倍に誇張):

![データ同化された変位分布](img/da_displacement_field.png)

- **でたらめ(左)**: 温度が全体に高すぎ(最大27.6℃)、一様に大きく膨張 → Uz が 0〜9.2µm と過大
- **データ同化後(中)**: ヒータ側(+X)が持ち上がり反対側が沈む**非対称な傾き** ―
  Uz −0.61〜0.92µm
- **真値(右)**: Uz −0.63〜0.96µm

**中央(同化後)と右(真値)は、変形の向き・大きさ・分布までほぼ一致**しています。
温度2点＋変位2点の観測だけで、**測っていない全体の変形形状まで言い当てた**わけです。
これが「データ同化された変位」です。

**変位の時刻歴アニメーション**(左=データ同化後 / 右=真値。各フレームで FrontISTR を実行):

![変位分布 DA vs 真値](img/da_vs_truth_displacement.gif)

温度が真値に一致するにつれ、そこから計算される変形形状(ヒータ側が持ち上がる傾き)も
左右で一致していく。

**ただし大事な注意**: この5点ROMでは、変位は「全体が一様に伸びる量」に
ほぼ比例し、すでに測っている温度2点と**ほとんど同じ情報**になってしまいます。
だからROMでは変位を「同化」に足しても効果が薄い(むしろ数値的に不安定)。
→ **ROMでは温度を同化し、変位は予測に使う**、という設計にしています。

変位が**本当に効く**のは、2万セルの温度場を丸ごと積分する OpenFOAM 版です。
そちらでは、温度2点だけの場合より温度場の推定が約4倍鋭くなりました
(RMSE 0.085K → 0.020K、`00_temp_displacement_da.md`)。
「模型を粗くすると、ある観測の価値が消える」― これはモデル縮約の良い教訓です。

## 8. ようやく数式(§2〜5を式にすると)

状態(推定したいもの)を1本のベクトルにまとめます:

$$x = [\, T_\mathrm{hot}, T_\mathrm{mid}, T_\mathrm{cold}, T_\mathrm{top}, T_\mathrm{core},\ q,\ h \,]$$

温度5点に加え、未知の発熱倍率 $q$ と放熱係数 $h$ も一緒に推定します
(拡大状態=パラメータも状態に入れる)。

観測 $y$(数点の温度)は、状態から観測を取り出す行列 $H$ で表せます:

$$y = H x + \varepsilon,\qquad \varepsilon \sim N(0, R)$$

$\varepsilon$ は測定ノイズ、$R$ はその大きさ(分散)。

**予測(前進)**: ROM の熱方程式でアンサンブルを時間発展。
各ノードのエネルギー収支は

$$C_i \frac{dT_i}{dt} = \sum_j K_{ij}(T_j - T_i) + q_i(t) - h(T_i - T_\mathrm{air})$$

(熱容量 × 温度変化 = 隣から流入する熱 + ヒーター − 逃げる熱)。

**修正(解析)**: 観測が来たら、各分身を次式で直します(カルマン更新):

$$x_a = x_f + K\,(y - H x_f)$$

- $x_f$: 予測(まだ直していない)、$x_a$: 修正後
- $y - H x_f$: 観測と予測のズレ(イノベーション)
- $K$: カルマンゲイン = 「ズレをどれだけ信じて直すか」の重み

$K$ は、アンサンブルのばらつき(標本共分散 $P_f$)と観測ノイズ $R$ の
兼ね合いで決まります:

$$K = P_f H^\top \left(H P_f H^\top + R\right)^{-1}$$

$P_f$ に「温度どうしの相関」が入っているので、**観測点の温度を直すと、
相関を通じて未観測点の温度まで直る**。これが §2 の「数点で全体が直る」の正体です。

詳しい導出と実装対応は `../103_0_openfoam_da_enkf/docs/05_theory_to_code.md`
(EnKF/PF の全数式↔コード対応表)を参照。

## 10. まとめ(この教材で分かること)

1. **データ同化 = 数点の測定で、間違った予測を正解へ引き戻す**
2. **アンサンブル** = 分身の集団で不確かさと相関を表す
3. **相関のおかげで、測っていない場所まで直る**
4. **ROM** = 一瞬で回る代用モデル。仕組みの理解に最適(本物は OpenFOAM 版)
5. **変位観測**の価値はモデルの細かさ次第 ― 粗いROMでは効かないが、
   全セルを積分する OpenFOAM では強力に効く
6. パラメータ(発熱量など)も**状態に混ぜて同時推定**できる
