# 温度分布・変位の時刻歴アニメはどう作っているか（種明かし）

`da_vs_truth_temperature.gif` / `da_vs_truth_displacement.gif` が「やけにリアル」に
見える理由を、作成パイプラインを一段ずつ示して種明かしする。
実装は `run/make_da_gifs.py`（約60行の本体）。

---

## 全体の流れ（4段）

```
[1] ROMでデータ同化      … 60メンバー・0→600s・温度2点+変位2点を同化
       ↓ 各時刻の「5点の温度」(同化後アンサンブル平均) と「真値の5点温度」
[2] 5点 → メッシュへ補間  … 重み行列 W で 5040節点の温度に再構成(行列積1発)
       ↓ 各時刻の「節点温度」
[3a] 温度GIF: 断面を描画   [3b] 変位GIF: 節点温度をFrontISTRに入れ変形を計算
       ↓ 31枚のPNG(左=同化後/右=真値)
[4] ImageMagickでGIF化    … 31フレームを連結
```

---

## [1] データ同化（左パネルの中身）

ROM双子実験（`dacore/twin_fem.py`）を1回走らせる。

- 60メンバーがでたらめ初期(10〜50℃)から出発
- 20秒ごとに **温度2点(hot/cold) ＋ 変位2点(上面Uz)** を同化
  （変位は演算子 $M$ によるアフィン観測 $u_z=M(T-T_{ref})$）
- 各観測時刻でのアンサンブル平均 $\bar T(t)\in\mathbb R^5$ を記録

これで手に入るのは、**時刻ごとの「5個の温度」**（同化後）と「真値の5個の温度」だけ。
まだ分布ではない。

## [2] 5点→分布への再構成（リアルに見える最大の理由）

5点をそのまま描くと点が5個あるだけ。そこで円筒メッシュ（5040節点）に
**逆距離加重補間(IDW)** で塗り広げる:

$$T_{mesh}(t)=W\,\bar T(t),\qquad
W_{p,i}=\frac{1/\lvert p-x_i\rvert^{2}}{\sum_j 1/\lvert p-x_j\rvert^{2}}\ \ (行和=1)$$

- W（5040×5）は形状だけで決まるので**最初に1回だけ**作る
- 以降、各時刻は行列積1発 → 31時刻ぶんでも一瞬
- IDWは距離に応じて滑らかに混ぜるので、**5点しか情報がないのに
  「なめらかな温度場」に見える**。これが“リアルさ”の正体（半分は補間の産物）

> 正直な注意：ヒータ直下の急勾配など細かい構造は5点では表現できない。
> 本当に正確な分布は OpenFOAM 版（20,696セル）の方。

## [3a] 温度GIFのフレーム

各時刻について PyVista で:
1. メッシュに `T_mesh` を貼る
2. `clip(normal="y")` で半分に切る（内部が見える断面表示）
3. 左パネル=同化後 / 右パネル=真値、色範囲は全フレーム共通（比較を公平に）
4. `t = ○○ s` の注記を入れて PNG 保存

## [3b] 変位GIFのフレーム（ここは本物のFrontISTR）

各時刻について:
1. [2]の節点温度（同化後と真値それぞれ）を **FrontISTR に入力**
2. 線形熱弾性静解析を実行（底面固定）→ 全節点の変位 $U$
3. 変形は数µmで見えないので **約2000倍に誇張**して節点座標に足す
4. 色は上面変位 Uz [µm]、左右パネル・色範囲・誇張倍率は全フレーム共通

つまり変位側は「絵として盛った」のではなく、**各フレームで実際にFEMを解いている**
（31時刻×2パネル=62回のFrontISTR実行、1回約1秒）。変形の傾き方・戻り方が
物理的に自然なのはこのため。

## [4] GIF化

31枚のPNGを ImageMagick で連結:

```
convert -delay 18 -loop 0 frames/*.png -layers Optimize -colors 128 out.gif
```

---

## なぜ「同化後」と「真値」がそっくりになるのか

データ同化が効いているから。t=0では左（でたらめ）と右（真値）が全く違うが、
最初の観測（t=20s）で左が右に吸い付き、以降は
- 温度: 5点が真値に一致 → IDW再構成した分布も一致
- 変位: 温度が一致 → FrontISTRの出力も一致

**左右が似ていること自体が「同化が成功した」ことの可視化**になっている。
