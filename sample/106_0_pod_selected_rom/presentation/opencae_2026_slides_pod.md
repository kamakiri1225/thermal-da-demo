## スライド構成（6枚）

### S1. なぜ低次元化するのか（問題提起）

**見せる図**：`oi_fullsolver_compare.png`（実ソルバOIの限界）

**言うこと**
- EnKFは「分身×サイクル×予報1回」＝ 実ソルバ（CHT＋FrontISTR）では1サイクルでも分オーダー
- 分身50〜200 × 10サイクル → **数時間〜数日**で現実的でない
- 実際、実ソルバのOIでは温度場は合う（0.090〜0.113 K）が、**発熱量 Q は8.9 W止まり**（真値15 W）

**キーメッセージ**：**予報モデルだけを軽くしたい**

---

### S2. PODとは ― 温度場を「型」に分解する

**見せる図**：`pod_modes.png`（モード1〜3の空間分布）

**言うこと**
- 温度場のスナップショットを並べた行列を特異値分解するだけ
- $X=\sigma_1u_1v_1^{\mathsf T}+\sigma_2u_2v_2^{\mathsf T}+\cdots$ ＝「空間の型」×「時間の動き」×「大きさ」の足し算
- 本ケースで出てきた型は物理的に読める：

| モード | エネルギー | 意味 |
|---|---|---|
| 1 | **91.8 %** | 全体が一様に昇温する型 |
| 2 | 8.08 % | ヒータ側と反対側の温度差の型 |
| 3 | 0.11 % | ほぼ効かない |

**キーメッセージ**：**2つの型で99.9 %** ＝ 温度場は実質2次元しか動いていない

**補足（聞かれたら）**：物理の知識は一切与えていない。行列を入れただけで出てくる。

---

### S3. 実装は3行（オープンCAE向けの核心）

**見せるもの**：コードそのもの（図なし・コードを大きく）

```python
mean = X.mean(axis=1)                              # セルごとの時間平均
Xc   = X - mean[:, None]                           # 変動だけにする
U, S, Vt = np.linalg.svd(Xc, full_matrices=False)  # ← モード分解
```

**言うこと**
- 専用ライブラリ不要。**numpy だけ**
- 入力は「セル数 × 時刻数」の行列（本ケース 20,696 × 121）
- `full_matrices=False` は必須（付けないと $N\times N$ を作ろうとして破綻）

**手順（口頭で流す）**：
1. `writeInterval` で等間隔出力 → 2. `writeCellCentres` で座標 → 3. 温度場を読んで行列化
→ 4. 平均を引く → 5. SVD → 6. エネルギーでモード数 → 7. ParaViewで目視 → 8. Q-DEIM

**キーメッセージ**：**明日から自分のケースでできる**

---

### S4. 代表点はデータが決める（Q-DEIM）

**見せる図**：`qdeim_points.png`（選ばれた5点の3D位置）＋ `qdeim_concept.png`（なぜその点か）

**言うこと**
- 「勘でノードを置く」のをやめ、**モード行列に枢軸付きQR**をかけて点を選ぶ
- アルゴリズムは素直な貪欲法：①一番強い点を選ぶ ②その方向を差し引く ③繰り返す
- 実際の残差の減り方（1点選ぶごとに「まだ分からない情報」が減る）：

| 順番 | 残差ノルム |
|---|---|
| 1点目 | 0.0369 |
| 3点目 | 0.0192 |
| 5点目 | 0.0143 → 差し引き後 **0.0000** |

**面白い所（つかみに使える）**：1点目は**ヒータ最近傍ではなく中央高さの点**。
Q-DEIMは「一番熱い点」でなく「**場全体をよく代表する点**」を選ぶ。

---

### S5. 勘で置くと何が起きるか（Q-DEIMの価値）

**見せる図**：表（または簡単な棒グラフ）

5点から全20,696セルを復元したときのRMSE：

| 選び方 | 復元RMSE |
|---|---|
| **Q-DEIM** | **0.00081 K** |
| ランダム 中央値 | 0.00220 K |
| ランダム 最良 | 0.00051 K |
| ランダム **最悪** | **1.396 K** |

**言うこと**
- 平均で見れば3倍差にすぎず、**運が良ければランダムでも勝てる**
- しかし**最悪ケースは1700倍**悪化する
- → **Q-DEIMの価値は「大外れを確実に避けること」**

**キーメッセージ**：勘で置くのはギャンブル。データで選べば下限が保証される。

### S6. できあがったROMと、正直な限界

**見せる図**：`rom_network.png`（5ノードのネットワーク）＋ `blog_temp_recon_anim.gif`（復元アニメ）

**成果**

| 項目 | 値 |
|---|---|
| ROM前進積分（0→600秒） | **約31 ミリ秒** |
| 校正残差（CHT履歴との差） | **0.0142 K** |
| 5点からの全場復元RMSE | 0.0008 K |

**限界（ここを正直に言うと信頼される）**

1. **PODモードは「入れたデータの型」**。形状・材料・BCだけでは決まらず、**運転条件込み**。
   加熱位置が変われば作り直しが必要（固有モードとは別物）
2. **エネルギー99.9 %は誤差3.3 %**（2乗の量なので）。モード数は物理量の誤差でも確認すべき
3. **体積重みを付けていない**。本ケースはセル体積が**最大/最小で192倍**あり、
   厳密には $\sqrt{V_i}$ 重み付きが正しい。実測すると支配モードは不変（cos 0.9998）で
   復元精度も同等（0.00072 → 0.00067 K）だが、**選点は5点中2点が入れ替わる**
4. **Q-DEIM点＝観測の最適点とは限らない**（復元に良い点と推定に良い点は別）
