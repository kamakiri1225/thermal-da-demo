## Q1. PODのモード分解は具体的にどうやったのか。Python？

Pythonの `numpy` だけ、実質3行。

```python
mean = X.mean(axis=1)                              # セルごとの時間平均
Xc   = X - mean[:, None]                           # 変動だけにする
U, S, Vt = np.linalg.svd(Xc, full_matrices=False)  # ← モード分解
```

`X` は「20,696セル × 121時刻」の温度行列、`U` の各列がPODモード。
`full_matrices=False` は必須（無いと $N\times N$ を作ろうとして破綻）。

📖 blog_004 §2-3 ／ 🔁 `run/svd_explained.py`

## Q2. `np.linalg.svd` は中で何をしているのか

行列を**足し算に分解**している。

$$X=\sigma_1u_1v_1^{\mathsf T}+\sigma_2u_2v_2^{\mathsf T}+\cdots$$

各項が「**空間の型** $u_k$ × **時間の動き** $v_k$ × **大きさ** $\sigma_k$ 」。
$\sigma$ が大きい順なので頭から数個取れば良い近似になる。
実データ3点×4時刻の完全展開あり（第1項＝全体の昇温84.2 %、第2項＝上下の偏り15.8 %、第3項＝ほぼ0）。

📖 blog_004 §2-3「数字で最後まで追う」

## Q3. 温度の時刻歴の行列を入れれば出てくるのか

**はい。** 必要なのは「各行が同じ場所を指していること」だけ。
メッシュ・境界条件・物性・方程式は不要なので、変位でも応力でも実験データでも同じ3行で動く。

## Q4. 境界条件（熱量・固定条件）が決まればモードは自然に決まるのか

**決まらない。** PODモードは**運転条件（加熱位置・出力・時間窓）込み**で決まる。

| | 固有モード | PODモード |
|---|---|---|
| 何で決まる | 形状・材料・境界条件**だけ** | **実際に起きたデータ** |
| 熱源の影響 | 受けない | **受ける** |

本ケースでモード1＝全体昇温、モード2＝左右の偏りと素直に出たのは熱源が1つだから。
**ヒータ位置を変えればモード2の形は変わる**。

## Q11. 変位観測を足すとなぜ温度まで良くなるのか

変位計は**温度誤差の重み付き和**を測っているから。

$$u-u^b=w^{\mathsf T}\delta T,\qquad K=\frac{Bw}{w^{\mathsf T}Bw+r}$$

誤差が共通の型 $\varphi$ で起きるなら $u-u^b=g\,a$ （ $g=w^{\mathsf T}\varphi$ ）となり、
**係数 $a$ が決まれば全点の温度が一斉に直る**。

$$\mathrm{Var}(a\mid u)=\frac{\sigma_a^2\,r}{g^2\sigma_a^2+r}$$

高W点（ $g$ 大）はほぼ確定、低W点（ $g\to0$ ）は何も学べない。
実測の3.52 K／2.43 K／0.86 K の差はこの $g$ の大小そのもの。

📖 blog_002 §3-7

## Q12. 「高感度／低感度」はどういうロジックで決めているのか

**温度センサと変位センサで定義が違う。**

| | 温度センサ | 変位センサ |
|---|---|---|
| 感度の定義 | $\partial T/\partial Q$ （発熱→温度） | $W=K_s^{-1}H_T$ の行ノルム（温度→変位） |
| 高感度の場所 | **ヒータ最近傍**（P2, 5.7） | **上端**（固定面から最遠） |
| 低感度の場所 | 反対側の底面（P4, 2.6） | 底面（拘束されて動けない） |

📖 blog_004 §4-4

## Q16. これはベイジアンネットワークで分析できるか

**できる。というよりそのもの。**
$Q,h \rightarrow T \rightarrow u \rightarrow$ 観測、という因果のDAGで、
データ同化は**この矢印を逆にたどる**操作。

ガウスなら $I(X;y)=-\frac12\ln(1-\Delta/\mathrm{Var}(X))$ で $\Delta$ と単調関係なので、
相互情報量で測っても**★の位置は完全に一致**する。

## Q21. LETKF とは何が違うのか（気象系の方から聞かれやすい）

本研究の実装は **確率的EnKF（摂動観測版）** で、LETKF ではない（`dacore/enkf.py`）。

| | **本研究：確率的EnKF** | **LETKF** |
|---|---|---|
| 更新の種類 | **確率的**。各メンバーに独立なノイズ $\varepsilon^{(i)}\sim N(0,R)$ を足す | **決定論的**（平方根フィルタ）。乱数を使わない |
| 更新式 | $z_a^{(i)}=z_f^{(i)}+K\,(y+\varepsilon^{(i)}-y_f^{(i)})$ | アンサンブル空間の変換行列 $\mathbf{W}$ で $Z_a=\bar z+dZ\,\mathbf{W}$ |
| 解く空間 | **状態空間**（$S=C_{yy}+R$ は観測数×観測数） | **アンサンブル空間**（$k\times k$、$k$＝メンバー数） |
| 局所化 | **なし** | **あり**。格子点ごとに近傍の観測だけ使う |
| 並列化 | 一括更新 | **格子点ごとに独立**＝大規模並列向き |
| 弱点 | 摂動のサンプリングノイズが乗る | 局所化で物理的バランスが崩れうる |

**LETKF ＝ ETKF（決定論的）＋ Localization（局所化）。**

### なぜ本研究で使わなかったか ― 状態が7次元しかないから

$$z=(T_1,\dots,T_5,\;Q,\;h)^{\mathsf T}$$

- **局所化が不要**：局所化は「状態が数百万次元・メンバー100個」で生じる**偽の相関**を切る技術。
  7次元・60メンバーでは偽相関がほぼ起きない
- **計算が軽い**：観測は2〜4個なので $S$ は最大 $4\times4$。アンサンブル空間で解く利点がない
- **摂動のノイズも問題にならない**：60メンバーで7次元なら標本が足りている

### ただし 104（実ソルバ版）なら LETKF が適切

104 は **20,696セルの温度場そのもの**を状態にしていた。この規模だと

- メンバー数（5〜60）≪ 状態次元（20,696）＝ **ランク不足**
- 遠いセル間に**偽の相関**が出る
- → **局所化が必要。LETKF が本来の選択肢**

（関連する別テーマで、局所化半径の設定を誤って失敗した経験あり）

### 答え方

> 「本研究は POD で状態を5次元に落としているので、**局所化が要らない領域**にいます。
> **低次元化と局所化は、どちらも『少ないメンバーで大きな系を扱う』ための手段**で、
> 本研究は前者を選びました。実ソルバを直接回す構成なら LETKF のほうが適切です。」

📖 実装 `dacore/enkf.py` ／ 低次元化の効果は blog_004 §4-0

## Q22. ベイズ最適化でパラメータを合わせるのと何が違うのか

コミュニティ内に**ベイズ最適化で CFD のパラメータを同定する**先行事例がある。
これは**競合ではなく、本研究の上流**にあたる。

| | ベイズ最適化 | **本研究（EnKF）** |
|---|---|---|
| 推定するもの | **パラメータのみ** | **状態（温度場）＋パラメータを同時に** |
| 時間の扱い | 全時刻の残差を**1つの目的関数に潰す** | **時刻ごとに逐次更新**（流れ依存の相関を使う） |
| 初期条件のズレ | 扱わない（既知と仮定） | **でたらめな初期値から直せる** |
| ソルバ呼び出し | 1評価＝フル解析1回。数十〜数百回 | 1サイクル＝メンバー数だけ前進 |
| 出力 | 最適点1つ（GPの事後分散から不確かさも） | **各時刻の推定値と不確かさ** |
| 向いている場面 | **オフラインで係数を合わせ込む** | **オンラインで状態ごと追従する** |

### 実は本研究の中でも使える

本研究の ROM 校正は、16個の係数（$C$ 5個＋$K$ 10個＋$h$ 1個）を
`scipy.optimize.least_squares` で同定している。**ここはベイズ最適化で置き換え可能**。

```
オフライン：CHT → POD → Q-DEIM → ROM係数の同定   ← ベイズ最適化の出番
オンライン：EnKF で状態＋発熱量を逐次推定          ← 本研究
```

### 答え方

> 「オープンCAEのコミュニティには**ベイズ最適化でパラメータを合わせ込む**知見が既にあります。
> 本研究はその**下流**です。オフラインで作ったモデルを、**オンラインで観測に追従させる**のが
> データ同化にあたります。両者はつながっていて、ROM係数の同定にはベイズ最適化が使えます。」

📖 ROM校正の実装 `run/build_calibrate_rom.py` ／ 解説 blog_004 §6-2
